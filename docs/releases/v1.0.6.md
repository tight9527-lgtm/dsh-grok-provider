## 中文

`1.0.6` 修复 DSH 附件库把带透明通道的图片规范化为 `image/webp` 后，Grok 请求在网络请求之前失败的问题。

发布后安装精确版本：

```sh
dsh plugin --profile web add dsh-grok-provider@1.0.6
```

### 修复

- 捕获阶段接受有界 `image/webp` 附件引用。
- 带 alpha 的 WebP 在写入 Responses `input_image` 前转为 PNG。
- 不透明 WebP 转为 JPEG。
- WebP 不会直接透传到 Grok；其他图片输入和精确 `grok-4.6` 路由边界保持不变。

### 验证

- 回归测试覆盖透明 WebP → PNG 和不透明 WebP → JPEG。
- 使用本机已登录的 Grok Build 凭据对 `grok-4.6` 完成真实透明 WebP 请求：HTTP 200、SSE 正常完成，wire MIME 为 `image/png`。

## English

`1.0.6` fixes pre-network failures when DSH normalizes transparent image attachments to `image/webp`.

Install the exact version after publication:

```sh
dsh plugin --profile web add dsh-grok-provider@1.0.6
```

### Fix

- Accept bounded `image/webp` attachment references during capture.
- Transcode alpha WebP to PNG before writing a Responses `input_image`.
- Transcode opaque WebP to JPEG.
- Never send WebP directly to Grok; existing image and exact `grok-4.6` route boundaries remain unchanged.

### Verification

- Regression coverage checks transparent WebP → PNG and opaque WebP → JPEG.
- A real `grok-4.6` transparent WebP request using the local authenticated Grok Build account returned HTTP 200, completed SSE, and sent `image/png` on the wire.
